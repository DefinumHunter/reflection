# Как написать тест для модуля

Руководство по синтаксису Reflection: какие файлы создать для нового модуля, что в каждом должно быть и что система сделает сама. Примеры взяты из `mac_q16` и `pe_mac_wrapper`, оба лежат в проекте и работают.

Команды запуска собраны отдельно в `COMMANDS.md`.

## Что откуда берётся

| Что | Откуда | Кто пишет |
|---|---|---|
| Соединения между модулями | RTL, разбирается автоматически | никто |
| Поведение модуля | golden-класс в `Components/` | ты |
| Список входов и выходов, ширины | TB в `hardware/tb/` | ты (объявления сигналов) |
| Как операция выглядит по тактам | `Modules/<модуль>/Protocol.py` | ты |
| Какие значения и в каком порядке подавать | `Modules/<модуль>/Scenario.py` | ты |
| Как сравнивать модель и RTL | `Modules/<модуль>/Checks.py` | ты (обычно одна строка) |
| Что считать проверенным | `Modules/<модуль>/Coverage.py` | ты |
| План теста, вся цепочка в одном месте | `Modules/<модуль>/Test.py` | ты |
| Независимая сверка соединений | `Modules/<модуль>/Connections.json` | ты (по желанию) |
| Драйвер, мониторы, scoreboard, запуск | `Engine/` | готово, не трогать |

Для нового модуля движок менять не нужно. Меняется одна строка в `Project.py`, остальное — новые файлы.

## Порядок работы

1. Положить RTL в `hardware/rtl/`, написать TB в `hardware/tb/`.
2. Написать golden для каждого модуля с логикой, которого ещё нет в `Components/`.
3. Добавить строку в `Project.MODULES`.
4. Создать папку `Modules/<модуль>/` с пятью файлами и пустым `__init__.py`.
5. Запустить `python -m Engine.Cover <модуль>`, потом `python -m Engine.Run <модуль>`.

Дальше каждый шаг по отдельности.

## 1. RTL и TB

Все файлы `hardware/rtl/*.sv` компилируются вместе, отдельно их нигде перечислять не надо.

TB — точка входа. В нём нет логики и нет стимула: только объявления сигналов и экземпляр модуля.

```systemverilog
`timescale 1ns / 1ps

module tb_pe_mac_wrapper;
    parameter int PIPELINE_STAGES = 4;

    logic               clk;
    logic               rst_n;
    logic signed [31:0] in_a;
    // ... one variable per DUT port
    logic signed [31:0] out_res;

    pe_mac_wrapper #(.PIPELINE_STAGES(PIPELINE_STAGES)) dut (.*);
endmodule
```

Правила:

- Имя файла совпадает с именем модуля TB: `tb_pe_mac_wrapper.sv`.
- Тактовый сигнал называется `clk`. Генератор такта в TB не пишется, такт запускает стенд (период 10 нс).
- Кто вход, а кто выход, определяется само: сигнал TB, который внутри никем не управляется, считается входом; сигнал, которым управляет выход модуля, считается выходом.
- Ширины сигналов берутся из объявлений в TB. Генератор проверяет по ним каждое значение.
- Параметр, объявленный в TB и переданный в модуль, можно менять из командной строки: `python -m Engine.Run mac_q16 PIPELINE_STAGES=7`. Модель получит то же значение.
- Блок `initial` с `$dumpfile` допустим, он игнорируется.
- В `.sv` только ASCII, включая комментарии.

## 2. Компонент: поведение модуля

Каждый модуль RTL относится к одному из двух видов.

**Модуль с логикой** (`always_ff`, `always_comb`, арифметика). Для него пишется golden в `Components/`. Внутрь его RTL система не заглядывает, только читает порты.

**Модуль-сборка** (только экземпляры других модулей и провода). Для него ничего писать не нужно: соединения читаются из RTL. `pe_mac_wrapper` — такой модуль, поэтому у него нет своего компонента.

Если в модуле без компонента найдётся `always`-блок, сборка модели остановится с ошибкой `has behavioural logic ... but its module has no component`. Выход один из двух: написать для него компонент или вынести логику в отдельный модуль.

### Описание компонента

```python
# Components/MacNode.py
from Engine.Core import LeafSpec

class MacQ16:
    ...

MacNode = LeafSpec(
    module="mac_q16",     # RTL module name
    golden=MacQ16,        # class, one object per RTL instance
    comb={"busy"},        # outputs visible in the same clock (optional)
)
```

Регистрировать компонент нигде не нужно: система сама находит все объекты `LeafSpec` в папке `Components/`. Два компонента для одного модуля RTL — ошибка.

### Класс golden

Один объект создаётся на каждый экземпляр модуля в RTL. Наследования нет, нужны только эти методы:

```python
class MacQ16:
    def __init__(self, PIPELINE_STAGES=4, pipe=None):
        self.tags = []                          # optional, for coverage
        self.pipe = pipe or [None] * PIPELINE_STAGES

    def start(self):                            # optional
        return {"out_res": self.pipe[-1], ...}

    def tick(self, i):
        ...
        return {"out_res": ..., "out_vld": ..., "out_sel": ..., "out_id": ..., "busy": ...}
```

| Часть | Правило |
|---|---|
| `__init__` | Получает **все** параметры экземпляра из RTL под их именами (`PIPELINE_STAGES=4`), поэтому каждый `parameter` модуля должен быть аргументом. Остальные аргументы — начальное состояние, по умолчанию `None`; его можно задать руками: `Project.model("mac_q16", init={"dut": {"vld_pipe": [0, 0, 0, 0]}})`. |
| `tick(i)` | Вызывается ровно один раз за такт. `i` — словарь всех входных портов, кроме `clk`. Возвращает словарь, где есть **каждый** выходной порт: лишний или пропущенный ключ даёт ошибку с именем экземпляра. |
| `start()` | Значения регистровых выходов до первого такта. Без него они стартуют как X. |
| `tags` | Список, куда golden дописывает имя ветки (`"sat_pos"`). Модель сама забирает и очищает его после каждого такта. |

### Регистровые и комбинационные выходы

Выход, **не** перечисленный в `comb`, считается регистровым: значение, которое вернул `tick`, появится на проводе в начале следующего такта. Это обычный триггер.

Выход из `comb` виден в том же такте. Он должен вычисляться из входов и из состояния **до** фронта.

Задержку больше одного такта golden держит сам, своим конвейером (см. `MacQ16.pipe`).

Порядок внутри `tick`, который не даёт ошибиться:

1. посчитать комбинационные выходы из входов и старого состояния;
2. обновить состояние, как это делает фронт `clk`;
3. вернуть регистровые выходы из нового состояния вместе с комбинационными.

### Значения

- Все значения — беззнаковые целые, сырые биты порта. Знаковую трактовку golden делает сам: `to_signed`, `saturate`, `q16` лежат в `Components/Fixed.py`.
- `None` означает X. Если вход X и от него зависит результат, результат тоже `None`.
- Сброс — обычный вход. Писать `if i["rst_n"] == 0:`, а не `if not i["rst_n"]:`. При `rst_n = X` Verilog идёт в ветку `else`, и golden должен сделать то же.
- Регистр без сброса в RTL не сбрасывается и в golden.

### Теги для покрытия

Тег ставится там, где golden выбирает ветку поведения:

```python
if tags is not None:
    tags.append("sat_pos" if res > 0x7FFFFFFF else
                "sat_neg" if res < -0x80000000 else "sat_none")
```

Ставить тег нужно только тогда, когда ветка действительно сработала на настоящих данных. `MacQ16` передаёт список тегов в арифметику только при `in_vld == 1`, иначе мусор в конвейере засчитался бы как проверенное насыщение.

## 4. Protocol.py: транзакции

Транзакция — одна операция модуля целиком, а не один такт. Это `dataclass`: поля — значения, которые она несёт; метод `cycles()` говорит, как она выглядит по тактам.

```python
from dataclasses import dataclass
from Components.MuxNode import LOAD_SUM, USE_SUM

IDLE = dict(rst_n=1, local_data=0, sub=0, in_a=0, in_b=0,
            sel=LOAD_SUM, in_id=0, issue_vld=0, mac_sel_in=0)

@dataclass
class MulSum:
    """c * (a + b), or c * (a - b) when sub = 1"""
    a: int = None
    b: int = None
    c: int = None
    sub: int = None
    id: int = None
    mac_sel: int = None

    def cycles(self):
        return [dict(sel=LOAD_SUM, in_a=self.a, in_b=self.b),
                dict(sel=USE_SUM, in_a=self.c, sub=self.sub, in_id=self.id),
                dict(issue_vld=1, mac_sel_in=self.mac_sel)]

@dataclass
class Reset:
    length: int = 5
    no_overlap = True

    def cycles(self):
        return [dict(rst_n=0)] * self.length
```

Правила:

- `cycles()` возвращает список словарей, по одному на такт. В словаре только те входы TB, которыми транзакция управляет в этом такте.
- Все остальные входы в этом такте берутся из `IDLE`. Поэтому `IDLE` обязан содержать **каждый** вход TB, иначе будет ошибка `nothing drives [...]: add them to IDLE`.
- `IDLE` — это «ничего не происходит»: значения, которые не меняют состояние модуля и не запускают операцию.
- Поле со значением по умолчанию `None` значит «заполнить по правилам из `Scenario.py`». Так направленный случай задаёт только важное: `MulSum(a=MAX, b=MAX, sub=0)`.
- `no_overlap = True` (без аннотации типа, это атрибут класса, а не поле) запрещает наложение на соседей. Нужен для сброса.
- Значения — сырые беззнаковые биты. Отрицательное число или число шире порта даёт ошибку с номером такта и именем транзакции.

## 5. Scenario.py: что подавать

В файле четыре вещи.

### Правила значений

```python
from Engine.Rules import bit, bits, corners, sequential

data = corners(CORNERS, p=0.2, otherwise=bits(32))

RULES = {
    "a": data, "b": data, "c": data, "local": data,
    "sub": bit(0.5),
    "id": sequential(1, 15),
    "mac_sel": bit(0.5),
}
```

Ключ — имя **поля транзакции**, а не сигнала. Правило общее для всех транзакций модуля: поле `a` в `MulAB` и в `MulSum` заполняется одним правилом. Поле без значения и без правила даёт ошибку.

| Правило | Что даёт |
|---|---|
| `bits(n)` | любое n-битное значение |
| `const(v)` | всегда `v` |
| `bit(p)` | 1 с вероятностью `p` |
| `between(lo, hi)` | целое из диапазона, границы включены |
| `one_of(values, weights=None)` | одно из значений |
| `corners(pool, p, otherwise)` | с вероятностью `p` значение из списка граничных, иначе правило `otherwise` |
| `sequential(lo, hi)` | lo, lo+1, …, hi, снова lo |

Своё правило — любая функция `rule(ctx) -> int`. В `ctx` есть `ctx.rng` (генератор случайных чисел этого прогона), `ctx.history` (уже созданные транзакции) и `ctx.field` (имя заполняемого поля). Модуль `random` напрямую не использовать, иначе прогон не воспроизведётся по seed.

### Рецепты значений

Функция, которая строит операнды под одно поведение и возвращает обычные числа:

```python
def sat_pair(rng, positive):
    """Both magnitudes >= 2^24: the product is past the 32-bit range."""
    ...
    return [a & 0xFFFFFFFF, b & 0xFFFFFFFF]
```

Рецепт не знает о транзакциях, поэтому его можно импортировать в сценарий любого модуля, чьи входы доходят до того же блока. `pe_mac_wrapper` берёт `small_pair`, `tie_pair`, `sat_pair` из `Modules/mac_q16/Scenario.py`.

### Классы стимула

Функция `f(ctx)`, которая возвращает транзакцию с частью полей. Остальные поля заполнят правила.

```python
def mul_sat(ctx):
    a, b = sat_pair(ctx.rng, positive=bool(ctx.rng.getrandbits(1)))
    return MulAB(a=a, b=b)
```

Класс нужен, когда случайные значения сами почти никогда не попадают в нужное поведение: ровно половина младшего разряда, насыщение суммы и так далее.

### Веса, паузы, направленные случаи

```python
WEIGHTS = {mul_ordinary: 16, mul_tie: 24, mul_sat: 6, MulAB: 6,
           sum_none: 15, sum_pos: 6, sum_neg: 6, MulSum: 6}

GAP = one_of([-1, 0, 1, 2, 3], weights=[4, 3, 2, 1, 1])

DIRECTED = [
    MulAB(a=q16(3), b=q16(2.5)),
    MulSum(a=MAX, b=MAX, c=q16(1), sub=0),     # sum saturates before the MAC
]
```

Ключ в `WEIGHTS` — класс стимула или сам класс транзакции. Класс транзакции означает «все поля по правилам».

`gap` — число тактов между концом одной транзакции и началом следующей:

| gap | Смысл |
|---|---|
| `2` | два такта `IDLE` между операциями |
| `0` | вплотную |
| `-1` | следующая начинается в последнем такте предыдущей (наложение) |

При наложении такты сливаются. Если две транзакции ставят на один вход в одном такте разные значения, это ошибка с именами обеих, а не тихая перезапись.

## 6. Checks.py: сравнение

Обычно одна строка:

```python
from Engine.Checks import exact as compare
```

| Правило | Что делает |
|---|---|
| `exact` | каждый выход каждый такт должен совпасть; такты, где модель говорит X, пропускаются |
| `only(signals, rule=exact)` | то же, но только для перечисленных сигналов |

Своё правило — функция `compare(expected, actual)`, которая получает два словаря за один такт и возвращает список расхождений `[(signal, expected, actual), ...]`. Пустой список значит, что такт совпал.

## 7. Coverage.py: что считать проверенным

Покрытие только считает и ничего не роняет. Есть три вида точек.

```python
from Engine.Coverage import Cross, Op, Tag
from Modules.mac_q16.Coverage import rounding, saturation    # reuse

kind = Op("kind", ["MulAB", "MulSum", "MulLocal"], of=lambda s: type(s.op).__name__)
gap  = Op("gap", ["overlap", "none", "pause"], of=_gap)

sum_op  = Tag("sum op", ["sum_add", "sum_sub"])
sum_sat = Tag("sum saturation", ["sum_sat_none", "sum_sat_pos", "sum_sat_neg"], at_least=10)

POINTS = [kind, gap, Cross(kind, gap), sum_op, sum_sat, Cross(sum_op, sum_sat),
          rounding, saturation]
```

| Точка | Что считает |
|---|---|
| `Op(name, bins, of)` | Отправленные транзакции. `of(s)` возвращает имя корзины; `s.op` — транзакция, `s.prev` — предыдущая (`None` у первой), `s.gap` — пауза перед ней. `None` означает «эта транзакция к точке не относится». |
| `Tag(name, bins)` | Теги из golden. Корзины — имена тегов. Считается по всем экземплярам вместе и по каждому отдельно. |
| `Cross(a, b, ignore=())` | Все пары корзин двух точек. Только одного вида: две `Op` на одной транзакции или две `Tag` из одного golden в одном такте. `ignore=[("x", "y")]` убирает невозможные пары. |

У каждой точки есть `at_least=N`: корзина считается закрытой после N попаданий, по умолчанию после одного. Для важных корзин одного случайного попадания мало.

Точки нижнего модуля импортируются готовыми, как `rounding` и `saturation` выше. Каждая точка из `Cross` должна быть и сама в списке `POINTS`.

Отчёт:

```
coverage: 66.7% (2/3 bins)
  saturation    2/3    no_sat=22 sat=30 never=0
              MISSING (need 5 each): never
```

- `MISSING` — корзины, в которые не попали нужное число раз.
- `values outside the bins` — `of` вернула значение, которого нет в списке корзин.
- `tags no point asks for` — golden выдал тег, которого нет ни в одной точке: опечатка или забытая точка.

## 8. Test.py: вся цепочка

```python
from Engine.Generator import Directed, Random
from . import Checks, Coverage, Protocol, Scenario
from .Protocol import Reset

SEED = 1
IDLE = Protocol.IDLE
RULES = Scenario.RULES

PLAN = [
    Directed([Reset(5)]),
    Directed(Scenario.DIRECTED, gap=0),
    Directed(Scenario.BACK_TO_BACK, gap=-1),
    Random(Scenario.WEIGHTS, count=200, gap=Scenario.GAP),
    Directed([Reset(2)], gap=1),
    Random(Scenario.WEIGHTS, count=100, gap=Scenario.GAP),
]

COMPARE = Checks.compare
COVERAGE = Coverage.POINTS
```

Система ищет в файле ровно эти имена: `SEED`, `IDLE`, `RULES`, `PLAN`, `COMPARE` и необязательное `COVERAGE`.

`PLAN` выполняется по порядку:

| Сегмент | Что делает |
|---|---|
| `Directed(ops, gap=0)` | эти транзакции в этом порядке |
| `Random(weights, count, gap=0)` | `count` транзакций, вид выбирается по весам |

`gap` в обоих случаях — число или правило.

После плана стенд сам подаёт 20 тактов `IDLE`, чтобы последние результаты успели выйти из конвейера.

## 9. Connections.json: сверка соединений

Модель берёт соединения из RTL, поэтому ошибку в проводах она повторит и тест пройдёт. Этот файл — независимое мнение: ты пишешь, что с чем должно быть соединено, и любое отличие от RTL останавливает сборку до симуляции.

```json
{
  "scope": "dut",
  "connections": {
    "rst_n":         ["u_mux.rst_n", "u_mac.rst_n"],
    "mac_sel_in":    ["u_mux.issue_sel"],
    "u_mux.out_sel": ["u_mac.sel"],
    "u_mac.out_res": ["out_res"]
  }
}
```

- Слева источник: вход TB (`rst_n`) или выход экземпляра (`u_mux.out_sel`). Справа все места, куда он идёт.
- Имя без точки — сигнал TB. Имя с точкой — порт экземпляра, к нему спереди добавляется `scope`.
- `clk` не перечисляется.
- Проверка строгая в обе стороны: соединение, которое есть в RTL, но не записано в файле, тоже ошибка.

Файл необязателен. Он нужен модулям-сборкам; для модуля из одного блока, как `mac_q16`, проверять нечего.

## 10. Запуск и разбор результата

```bash
python -m Engine.Cover new_module      # model only: is the stimulus legal, what does it cover
python -m Engine.Run new_module        # real simulation against the RTL
```

Сначала `Cover`: он за доли секунды ловит ошибки в компоненте, протоколе и сценарии и показывает дыры в покрытии. Симулятор для него не нужен, но в `Test.py` должен быть `COVERAGE`.

Успешный прогон заканчивается строками:

```
seed 1
127 cycles, 250 values matched, 4 skipped (model X), 0 mismatches
TESTS=1 PASS=1 FAIL=0
```

Чтобы модуль проверялся командой `python -m pytest tests`, его надо дописать в список в `tests/test_uvm.py` (`test_bench_passes_on_correct_rtl`).

### Что означают ошибки

| Сообщение | Причина | Где чинить |
|---|---|---|
| `cycle 6: out_sum expected 0xff, got 0xfe` | Модель и RTL разошлись. `expected` — модель, `got` — RTL. | Сначала решить, кто прав. Спецификация — golden, если только он не списан с RTL. |
| `scoreboard compared nothing` | Модель весь прогон выдавала X. | Нет сброса в начале `PLAN` или golden возвращает `None`. |
| `ConnectionMismatch: ... expected, but in the RTL ... is driven by ...` | RTL соединён не так, как записано. | RTL или `Connections.json`. |
| `CombLoopError: ... waits on ...` | Комбинационная петля: экземпляры ждут выходы друг друга. | Лишнее имя в `comb` или настоящая петля в RTL. |
| `has behavioural logic ... but its module has no component` | Модуль с логикой без golden. | Написать компонент. |
| `connection '...' is not supported yet` | В подключении порта выражение, срез или конкатенация. | См. ограничения. |
| `golden of 'dut.u_mux': missing outputs [...]` | `tick` вернул не все порты или лишние. | Golden. |
| `nothing drives [...]: add them to IDLE` | В `IDLE` нет входа TB. | `Protocol.py`. |
| `drives [...], which are not TB inputs` | Опечатка в имени сигнала в `cycles()` или `IDLE`. | `Protocol.py`. |
| `X.f is not set and the scenario has no rule for 'f'` | Поле без значения и без правила. | `RULES` в `Scenario.py`. |
| `does not fit in N bits` / `is negative` | Значение шире порта или знаковое. | Рецепт или правило: маскировать `& 0xFFFFFFFF`. |
| `#12 MulSum[0] drives sel=1, but #11 MulAB[1] already drives sel=0` | Наложение транзакций с конфликтом. | Увеличить `gap` или поставить `no_overlap`. |

Упавший случайный прогон повторяется один в один: `python -m Engine.Run <модуль> seed=N`, где N — число из строки `seed N` в логе.

## Правила именования

| Что | Правило | Пример |
|---|---|---|
| Модуль RTL, файл | `snake_case`, имя файла равно имени модуля | `pe_input_mux.sv` |
| TB | `tb_<модуль>`, имя файла равно имени модуля TB | `tb_pe_mac_wrapper.sv` |
| Экземпляр модуля в TB | `dut` | `pe_mac_wrapper dut (.*);` |
| Экземпляры внутри сборки | `u_<имя>` | `u_mux`, `u_mac` |
| Тактовый сигнал, сброс | `clk`, `rst_n` (активный 0) | |
| Сигналы TB | те же имена, что у портов модуля | подключение через `.*` |
| Файл компонента | `<Имя>Node.py` | `MacNode.py` |
| Класс golden | имя модуля в `CamelCase` | `MacQ16`, `PeInputMux` |
| Объект `LeafSpec` | `<Имя>Node` | `MacNode` |
| Папка модуля | `Modules/<модуль>/`, имя как у модуля RTL | `Modules/pe_mac_wrapper/` |
| Файлы в папке | `Protocol.py`, `Scenario.py`, `Checks.py`, `Coverage.py`, `Test.py` | |
| Транзакция | `CamelCase`, по смыслу операции | `MulSum`, `Reset` |
| Поле транзакции | короткое, строчными; одно имя значит одно и то же во всех транзакциях модуля | `a`, `sub`, `id` |
| Рецепт значений | `<что>_pair(rng, ...)`, возвращает числа | `sat_pair` |
| Класс стимула | `snake_case`, функция `f(ctx)` | `mul_sat`, `sum_pos` |
| Тег | `<группа>_<ветка>`, уникален во всём проекте | `sat_pos`, `sum_sat_pos` |
| Константы режимов | `ЗАГЛАВНЫМИ`, лежат в файле компонента | `LOAD_SUM`, `USE_LOCAL` |

Тег должен быть уникален во всём проекте, потому что точка `Tag` ищет его по имени во всех экземплярах сразу. Поэтому насыщение суммы в мультиплексоре называется `sum_sat_pos`, а не `sat_pos`, который уже занят умножителем.

Идентификатор 0 зарезервирован под «нет транзакции», настоящие операции получают 1..15.

Сейчас сами инструменты проверяют только часть правил: имя файла TB, имена входов, наличие каждого выхода в golden. Остальное пока соглашение.

## Что пока не поддерживается

- **Несколько тактовых сигналов.** Модель считает один `clk`. Модули с `clk800`/`clk400` проверить нельзя.
- **Срезы и конкатенации в подключениях.** Порт подключается именем или элементом массива с постоянным индексом (`bus[3]`). `.a(x[7:0])`, `.a({x, y})`, `.a(x + 1)` дают ошибку.
- **Логика в модуле-сборке.** Даже `assign y = a & b;` в обёртке требует вынести это в модуль с компонентом. Простое `assign a = b;` разрешено.
- **Стимул, зависящий от выходов.** Генератор не видит ответ модуля: дождаться `busy = 0` и только потом слать нельзя. Паузы задаются заранее через `gap`.
- **Крест операции с тегом.** `Cross` соединяет только точки одного вида.
- **Порог покрытия.** Отчёт показывает дыры, но тест из-за них не падает.
- **SVA.** Утверждения будут в `hardware/sva/` и запускаться в Xcelium.
- **Выбор симулятора.** Сейчас только Icarus.
